# МСтрой тестовое

Дерево элементов хранилища на Vue 3, TypeScript, Vite и AG Grid Community. Данные загружаются из `json-server`, поддерживаются раскрытие/сворачивание групп, нумерация видимых строк и категории.

## Требования

- Node.js 20+
- npm

## Запуск

```bash
npm install
cp .env.example .env
```

В первом терминале запустить API:

```bash
npm run server
```

Во втором — приложение:

```bash
npm run dev
```

По умолчанию API доступен на `http://localhost:3000`, приложение — на адресе, который выведет Vite.

## Переменные окружения

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `VITE_API_URL` | Базовый URL API | `http://localhost:3000` в dev, относительный путь в production |

Если `VITE_API_URL` не задан в production-сборке, запросы идут на текущий origin (`/items`).

## Структура

Проект организован по FSD:

- `src/shared/ui/TreeTable` — self-contained generic-компонент таблицы-дерева. Внутри: `types` (`TreeNode`, `TreeRow`, `ExpanderLabels`), `model` (`TreeStore<T>` и построение видимых строк), `config` (expander, стили и константы) и `ui` (`TreeTable` с ленивым `TreeGrid`). Наружу экспортируются только `TreeTable`, `TreeRow` и `ExpanderLabels`. Конфиг столбцов передаётся пропсом.
- `src/entities/SomeEntity` — тип элемента и API для загрузки.
- `src/features/ItemsTable` — контейнер фичи: загрузка данных, конфиг столбцов и шапка таблицы.
- `src/shared` — `BaseApi`, общие типы, конфиг API и глобальные стили.
- Тесты лежат в подпапках `__tests__` внутри соответствующего FSD-сегмента.

## Данные

Элемент имеет вид:

```ts
type SomeEntityItem = {
  id: number | string
  parent: number | string | null
  label: string
}
```

`TreeNode` — общий контракт дерева из `shared/ui/TreeTable`: `{ id, parent }`. Сущность и дерево — разные типы; `SomeEntityItem` структурно совместим с `TreeNode`, поэтому его можно передать в generic `TreeTable` без маппинга. Корневые элементы ссылаются на `parent: null`. Идентификаторы уникальны, числовые и строковые значения не смешиваются.

## TreeStore

`TreeStore<T extends TreeNode>` не зависит от сущности и не содержит реактивности: данные приходят в него через `setItems`, а обновление UI обеспечивается пропсом `items` у `TreeTable`.

- `getAll()` — все элементы в исходном порядке.
- `getItem(id)` — элемент по id.
- `getChildren(id)` — прямые дети в порядке добавления; `getChildren(null)` возвращает корни.
- `getAllChildren(id)` — все потомки в depth-first порядке, без самого элемента.
- `getAllParents(id)` — сам элемент и его предки от элемента к корню.
- `addItem(item)` — добавляет элемент; запрещает дубли id, элемент, являющийся родителем самому себе, и перенос под несуществующего родителя.
- `removeItem(id)` — удаляет элемент вместе с поддеревом.
- `updateItem(item)` — обновляет элемент; запрещает перенос в собственное поддерево и под несуществующего родителя.
- `setItems(items)` — заменяет данные; отклоняет дубли id до изменения состояния.
- Обходы `getAllChildren`, `getAllParents` и построение видимых строк защищены от циклов: каждая ветка посещается один раз.

## Поведение таблицы

- `ItemsTable` загружает элементы и передаёт их в `TreeTable` пропсом `items`; при изменении массива дерево пересобирается, раскрытие сбрасывается к корневым группам с детьми.
- Колонки задаются фичей через `columnDefs`: «№ п/п», «Категория» и «Наименование». Shared-компонент добавляет служебную колонку-expander.
- «Категория» вычисляется по наличию детей: `Группа` или `Элемент`.
- Счётчик в шапке показывает общее количество загруженных элементов, а не только видимых.
- AG Grid вместе с темой и модулями живёт в ленивом `TreeGrid`, который подгружается внутри `TreeTable`.
- Раскрытие и сворачивание обновляют только затронутое поддерево, а грид получает изменения через `applyTransaction` с `addIndex`, чтобы новые строки вставлялись после группы, а не в конец списка; полная пересборка строк выполняется только при замене `items`.

## Производительность

- AG Grid вынесен в отдельный ленивый чанк `TreeGrid`; основной бандл не содержит `ag-grid-community`.
- Раскрытие/сворачивание не пересобирает весь список: обновляется только затронутое поддерево.
- Изменения передаются в AG Grid через `applyTransaction`, поэтому грид не диффает весь `rowData`.
- Номер строки вычисляется по `rowIndex`, а неизменённые объекты строк переиспользуются из кэша.
- Полная пересборка видимых строк выполняется только при замене `items`.
